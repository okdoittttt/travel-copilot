## 1. 목적

하루 일정에서 **장소와 장소 사이 이동시간·거리**를 보여주고, 그날 장소들을 **앱 안의 지도**에 표시한다. 계획한 시각으로는 이동이 빠듯한 구간을 미리 알려준다.

F3이 "어디에 갈지"였다면 F4는 "그 순서대로 갈 수 있는지"를 보여준다. 이동시간은 Google 약관상 저장할 수 없어서, 일정을 볼 때마다 서버가 계산해서 응답에만 담는다.

## 2. 사용자 시나리오

**이동 구간 보기**
1. 일정 탭에서 날짜를 고르면, 항목 사이마다 이동 구간이 보인다: "🚇 대중교통 21분 · 3.9km"
2. 이동수단을 안 고른 구간은 "이동수단을 선택하세요", 장소가 없는 항목 앞뒤는 "— 장소 없음"
3. 앞 일정의 시작 시각 + 머무는 시간 + 이동시간이 다음 일정 시작 시각보다 늦으면 그 구간이 주황색: "⚠ 10분 늦음"

**지도 보기**
1. 일정 탭 위쪽의 [목록 | 지도] 중 지도 → 그날 장소들이 순서 번호가 붙은 마커로 보인다
2. 마커를 누르면 장소 정보 시트(S10)

**연결이 안 될 때**: 이동 구간 자리에 "이동시간을 불러오지 못했습니다 [다시 시도]". 일정 목록은 그대로 보인다 (오프라인 캐시는 F6)

## 5. 핵심 설계 결정

### 5.1 이동시간 계산 — Routes API Essentials만

2026-11-15 공식 SKU 페이지 확인:

| 요청 방식 | 등급 | 무료 / 월 | 이후 1,000회당 |
|---|---|---|---|
| `computeRoutes`, 교통 미반영 | **Essentials** | 10,000 | $5 |
| 실시간 교통 반영 (`TRAFFIC_AWARE`) | Pro | 5,000 | $10 |

- 구간마다 `computeRoutes`를 한 번씩 부른다. 출발·도착은 **place_id**로 넘긴다 (좌표가 없어도 계산 가능, 좌표 갱신 호출을 줄임)
- 차량은 `routingPreference: TRAFFIC_UNAWARE`로 고정하고 출발 시각을 보내지 않는다 (실시간 교통 = Pro)
- 대중교통·도보는 교통 옵션이 없어 Essentials
- 필드 마스크: `routes.duration,routes.distanceMeters`만. 상수로 고정
- `computeRouteMatrix`는 쓰지 않는다: 이동수단이 구간마다 다른데 Matrix는 요청 하나에 이동수단 하나이고, 출발×도착 **조합 수만큼** 과금된다 (N개면 N², 필요한 건 N-1개)
- 같은 날의 구간은 **동시에 최대 5개씩** 부른다. 하루 최대 49구간 (항목 50개)
- 실패한 구간만 `unavailable`, 나머지는 정상으로 응답한다

### 5.2 저장하지 않는다 (약관)

공식 정책: 지도 콘텐츠는 서비스 약관이 명시적으로 허용한 것만 저장할 수 있고, 허용 예외는 place_id(기한 없음)와 좌표(30일)뿐이다. 이동시간·거리는 예외가 아니다.

- 서버: 이동시간을 DB·메모리 어디에도 보관하지 않는다. 요청마다 계산
- 앱: 응답을 **화면이 열려 있는 동안만** 메모리에 들고 있다. 날짜를 바꾸거나 화면을 나갔다 오면 다시 받는다. 기기 DB에 저장하지 않는다
- 비용 관리는 캐시 대신 **호출 제한**으로 한다 (5.5)

### 5.3 좌표 30일 관리 (F3에서 미룬 자동 실행)

- **갱신**: 하루 일정을 계산할 때, 장소는 있는데 좌표가 30일 지났거나 없는 항목은 Places 장소 상세(Essentials, F3과 같은 필드 마스크)로 좌표를 다시 받아 DB에 저장한다. 지도 마커에 좌표가 필요해서다
- **삭제**: 서버가 떠 있는 동안 **6시간마다** F3의 정리 작업(`expire_locations`)을 실행한다 (서버 시작 시 백그라운드 작업). 아무도 안 여는 여행의 오래된 좌표도 지워진다
- 운영에서 서버를 여러 대로 늘리면 한 대만 실행하도록 바꾼다 (지금은 1대)

### 5.4 앱 지도 — Maps SDK (무료, 맵 ID 없이)

- 패키지: `google_maps_flutter` (Flutter 공식)
- iOS 구현은 **Google Maps SDK 10 기반**(`google_maps_flutter_ios_sdk10`)을 쓴다
  - 이 앱은 Swift Package Manager로 빌드하는데(Podfile 없음), 예전 구현은 SPM을 지원하지 않고 업데이트도 끝났다
  - **SDK 10은 iOS 16 이상이 필요하다 → 앱 최소 iOS를 15에서 16으로 올린다** (iPhone 8 이후 기기는 모두 iOS 16 지원)
- 요금: 공식 요금표에서 "Maps SDK"는 **무제한 무료**. 단 **맵 ID를 쓰면 유료(Dynamic Maps, 월 10,000회 무료)** 로 바뀌므로 맵 ID를 쓰지 않는다
- 마커: 순서 번호(1, 2, 3…), 누르면 S10 장소 정보 시트. 경로선 없음
- 좌표는 `GET /days` 응답에서 받아 화면에서만 쓴다 (기기에 저장하지 않음, 06-api 3.3)

### 5.5 지도 키 — 앱에 들어가지만 git에는 넣지 않는다 (T20)

지도 키는 앱 안에 들어가므로 앱을 풀면 꺼낼 수 있다. 그래서 키 자체보다 **키 제한**이 방어선이다.

| 항목 | 처리 |
|---|---|
| 키 분리 | 서버 키(Places·Routes)와 **다른 키**. 앱 키는 Maps SDK for iOS만 허용 + iOS 번들 ID(`com.okdoittttt.travelcopilot`)로 제한 |
| git | **이 저장소는 공개**다. 키를 `AppDelegate.swift`에 직접 쓰지 않고, git에서 제외한 `ios/Flutter/Secrets.xcconfig`에 둔다 → `Info.plist`의 `GMSApiKey` 값으로 → `AppDelegate`가 읽어서 `GMSServices.provideAPIKey` |
| 키가 없을 때 | 빌드는 되고, 지도 탭만 "지도를 사용할 수 없습니다" |
| 예시 파일 | `ios/Flutter/Secrets.xcconfig.example` (빈 값) 커밋 |
| 검사 | gitleaks가 Google API 키 형식을 잡는지 확인 (`AIza…`). 릴리스 빌드 키 검사는 R |

- 서버 키에는 **Routes API를 추가로 허용**한다 (Places API (New) + Routes API). 같은 서버 키를 쓴다

### 5.6 시각 불일치 경고 — 앱에서 계산

- 조건: 앞 항목과 다음 항목 모두 `start_time`이 있고, 구간이 `ok`일 때
- 앞 시작 + 앞 머무는 시간(없으면 0) + 이동시간 > 다음 시작 → 경고, 늦는 분 수 표시
- 서버가 아니라 앱에서 계산한다: 사용자 입력값과 응답만으로 계산되는 순수 함수라 테스트가 쉽고, 서버 응답 형식을 단순하게 유지한다
- 날짜를 넘기는 일정(자정 넘김)은 경고하지 않는다

## 6. API

| 메서드 | 경로 | 권한 | 성공 |
|---|---|---|---|
| GET | `/trips/{trip_id}/days/{date}` | V 이상 | 200 하루 일정 + 이동 구간 |

```json
// GET /trips/{trip_id}/days/2026-12-24 → 200
{
  "date": "2026-12-24",
  "items": [ { "…F3 항목 객체…" } ],
  "legs": [
    { "from_item_id": "…", "to_item_id": "…", "mode": "transit",
      "status": "ok", "duration_seconds": 1260, "distance_meters": 3900 },
    { "from_item_id": "…", "to_item_id": "…", "mode": null,
      "status": "no_mode", "duration_seconds": null, "distance_meters": null }
  ]
}
```

- `legs`는 항목 순서대로 인접한 쌍마다 하나 (항목 N개 → N-1개). `mode`는 **도착 항목**의 `travel_mode` (F3 정의: "이전 항목에서 이 항목까지")
- `status`: `ok` / `no_location`(어느 한쪽에 장소 없음) / `no_mode`(이동수단 미선택) / `unavailable`(Google이 경로를 못 찾음, 외부 오류, 타임아웃)
- 항목의 `location`은 5.3에 따라 갱신된 값
- 날짜가 여행 기간 밖이면 422, 그날 항목이 없으면 `items: [], legs: []`

| 상황 | 응답 |
|---|---|
| 비멤버 | 404 |
| 호출 제한 초과 (사용자당 **시간당 120회**, 06-api 5절) | 429 |
| 서버에 Routes용 키 없음 | 200, 모든 구간 `unavailable` (일정은 보여야 하므로 503 아님) |
| Google 실패 | 200, 해당 구간만 `unavailable` |

## 10. 테스트 계획

- **서버 단위**: Routes 응답 파싱·검증(`"1260s"` 형식), 구간 상태 결정(no_location·no_mode), 동시 호출 제한
- **서버 API**: 하루 조회 정상·빈 날·기간 밖 422·비멤버 404, 좌표 갱신(30일 지난 항목은 Places 다시 호출 후 DB 저장), 키 없음 → 모두 unavailable
- **보안**: 8절 전부 (`tests/security/test_routes.py`)
- **앱**: 구간 모델 변환, 시각 불일치 계산(경계값: 딱 맞음, 1분 늦음, 시각 없음, 자정 넘김), 구간 표시 문구, 목록↔지도 전환, 키 없을 때 안내
- **수동 확인 (iOS 시뮬레이터, 실제 키)**
  1. 장소 3곳, 이동수단 섞어서 → 구간마다 시간·거리
  2. 시작 시각을 빠듯하게 → 주황 경고
  3. 지도 탭 → 마커·번호·S10
  4. Google Cloud 콘솔에서 Routes 호출 수 = 구간 수인지

## 12. 열린 질문

- **iOS 최소 버전 16**: 5.4의 이유로 올린다. 반대하면 예전 구현(iOS 15, SPM 미지원)을 쓸 수 있지만 업데이트가 끝난 패키지라 권하지 않는다
- **대중교통 출발 시각**: 지금은 출발 시각을 보내지 않아 "지금 출발" 기준 대중교통 시간이 나온다. 일정의 시작 시각 기준으로 계산하려면 출발 시각을 보내야 하는데, 공식 문서의 요금 설명이 "출발 시각을 now로 하면 실시간 교통(더 비쌈)"이라고만 되어 있어 대중교통에 미치는 영향이 불분명하다. 구현 때 Google Cloud 콘솔의 과금 SKU로 확인하고 정한다
- **경로 결과 캐시**: 정책상 근거를 찾지 못해 캐시하지 않는다. 비용이 문제가 되면 서비스 약관(Service Specific Terms)을 확인한 뒤 다시 검토
- **한국 내 도보·차량 경로 없음** (2026-11-15 수동 확인 중 발견): Google Routes는 한국에서 대중교통만 경로를 돌려주고, 도보·차량은 오류 없이 빈 응답(`{}`)을 준다 (서울역→역삼역: 대중교통 34분·16.2km, 도보 빈 응답). 앱에는 해당 구간이 "이동시간을 알 수 없어요"로 보인다. 국내 여행을 지원할 때 한국 구간만 다른 경로 API(카카오모빌리티·네이버 지도 등)로 보내는 방안을 검토한다. 그때 확인할 것: 요금·무료 범위, 결과 저장 약관, 좌표계(WGS84 여부), 서버 대리 호출·키 분리 구조 재사용

## 13. 구현 결과 (2026-11-15)

**테스트**: 서버 298개(F4 추가 35개), 앱 82개(F4 추가 11개) 통과. lint·타입 검사 통과.

**실행 확인**
- iOS 빌드: 최소 iOS 16, Google Maps SDK 10(SPM으로 받음) 빌드 성공. 지도 키 없이 실행해도 앱이 정상으로 뜬다
- 서버: 실제 키로 장소 3곳의 하루 조회 → Google Routes가 **403** (Routes API 미사용 설정 또는 서버 키 API 제한). 설계대로 구간만 `unavailable`, 일정은 200. 로그에 키·에러 본문 없음
- 화면 조작(이동 구간 줄, 늦음 경고, 지도 마커)은 Routes API·지도 키 설정 후 개발자 확인 대기

**방어 제거 시험**

| # | 끈 것 | 실패한 테스트 |
|---|---|---|
| 1 | 하루 조회 사용자별 제한 | `test_day_view_rate_limit` |
| 2 | 필드 마스크를 `*`로 | `test_routes_request_is_essentials_only` |
| 3 | 동시 호출 제한(5 → 1000) | `test_routes_calls_bounded` |
| 4 | 차량 `TRAFFIC_UNAWARE` → `TRAFFIC_AWARE`(Pro) | 등급 테스트, 단위 요청 테스트 |

- 시험 3은 처음에 통과해 버렸다. 테스트가 동시 호출 상한을 **코드의 상수와 비교**하고 있어서, 상수를 바꾸면 기준도 같이 바뀌었기 때문. 명세 값(5)과 직접 비교하도록 고친 뒤 실패를 확인했다

**명세와 달라진 점·알아둘 점**
- Routes는 별도 키 없이 **F3의 서버 키(`GOOGLE_PLACES_API_KEY`)를 같이 쓴다**. Google Cloud에서 그 키의 API 제한에 Routes API를 추가해야 한다
- 앱이 지도 키 유무를 아는 방법: iOS `AppDelegate`가 작은 채널(`travelcopilot/config`)로 알려준다. 키 없이 지도를 만들면 Google Maps SDK가 앱을 종료시키기 때문 (F1 Google 로그인 때와 같은 종류의 문제)
- 이동 구간 줄은 별도 행이 아니라 **각 일정 위쪽에 붙여서** 그린다. 길게 눌러 순서를 바꿀 때 구간 줄이 일정과 같이 움직여야 해서
- 순서를 바꾸면 화면의 새 순서와 맞는 구간만 보여주고(옛 구간은 숨김), 서버에서 새로 받으면 다시 채운다
- 좌표 갱신은 "장소가 아직 같을 때만" 저장한다. 좌표를 받는 사이 다른 멤버가 장소를 바꿨다면 옛 좌표로 덮어쓰지 않는다
- 서버 테스트에서는 6시간 정리 작업을 끈다 (`LOCATION_CLEANUP_INTERVAL_SECONDS=0`)

**수동 확인 (2026-11-15, iOS 시뮬레이터)**
- 지도: 번호 마커·장소 시트 정상. 같은 좌표의 일정만 있으면 화면 맞춤 영역 크기가 0이 되어 최대 배율로 확대되는 버그 발견 → 중복 좌표를 합쳐 한 곳이면 14배율로 수정
- 이동시간: 로마 구간 도보·차량 정상. 서버 키 API 제한에 Routes API가 빠져 있어 처음엔 403 → 추가 후 정상 (적용까지 몇 분)
- 한국 구간은 도보·차량이 빈 응답 (12절 열린 질문)
- Google Cloud 할당량·예산 알림·키 API 제한 축소는 무료 체험 중이라 유료 전환 시 설정 (threat-model T23)
