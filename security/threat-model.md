# Travel Copilot 위협 모델

> 상태: 초안 v0.1 (2026-11-08)
> 범위: MVP — M1 일정·동선, M4 협업·오프라인 바우처 지갑, 소셜 로그인
> 기준 문서: [../docs/prd.md](../docs/prd.md), [../docs/mvp.md](../docs/mvp.md)
> 갱신 규칙: 새 기능 설계, 점검 결과, 사고가 생길 때마다 갱신하고 맨 아래 변경 이력에 남긴다

## 1. 시스템 개요

```
 [Flutter 앱] ─────── HTTPS ───────> [Nginx] ──> [FastAPI 서버] ──> [PostgreSQL]
   │ 로컬 저장소                                    │   │
   │  - 토큰 (Keychain/Keystore)                    │   └──> [오브젝트 스토리지: 바우처 파일]
   │  - 일정 캐시 (SQLite)                          │
   │  - 바우처 캐시 (암호화 파일)                    ├──> [Google Places / Routes API]
   │                                               └──> [카카오 / Apple / Google OIDC]
   ├── 소셜 로그인 SDK ──> [카카오 / Apple / Google]
   ├── 지도 SDK ──> [Google Maps] (지도 표시용 키)
   └── 바우처 다운로드 ──> [오브젝트 스토리지] (짧게 만료되는 URL)

 초대 링크: [단톡방 등] ──> Universal Link / App Link ──> [Flutter 앱] ──> 서버
```

### 신뢰 경계

| # | 경계 | 넘어오는 것 |
|---|---|---|
| B1 | 인터넷 ↔ 서버 | 앱의 모든 API 요청 (신뢰하지 않음) |
| B2 | 서버 ↔ 외부 서비스 | Google 응답, OIDC 공개키·토큰 |
| B3 | 서버 ↔ 저장소 | DB 쿼리, 파일 읽기·쓰기 |
| B4 | 앱 ↔ 기기 | 로컬에 저장한 토큰·캐시 (기기를 잃어버리면 남의 손에) |
| B5 | 외부 채널 ↔ 앱 | 초대 링크 (누가 보냈는지 모름) |

## 2. 자산

| 자산 | 내용 | 노출되면 |
|---|---|---|
| **바우처 파일** | 항공권·호텔 확인서. 이름, 여권번호, 생년월일, 예약번호가 들어 있을 수 있음 | 신원 도용, 예약 변경·취소 | 
| **여행 일정** | 목적지, 날짜, 숙소 위치 | **집이 비는 기간**과 현지 위치 노출 → 빈집털이, 스토킹 |
| 계정·토큰 | 소셜 로그인 식별자, 액세스·리프레시 토큰 | 계정 탈취 → 위 자산 전체 |
| 동행자 관계 | 누가 누구와 여행하는지, 이메일·닉네임 | 사생활 노출 |
| 서버 비밀값 | DB 비밀번호, 토큰 서명 키, 파일 암호화 키 | 전체 데이터 노출 |
| Google API 키·요금 | 서버용 키, 지도용 키 | 요금 폭탄 (denial of wallet) |

## 3. 공격자

| 공격자 | 할 수 있는 것 | 노리는 것 |
|---|---|---|
| A1 외부 공격자 | 계정 없이 API 호출, 자동화 도구 | 인증 우회, 대량 요청, 서버 취약점 |
| A2 악의적 일반 사용자 | 정상 계정으로 로그인, 요청 조작 | 남의 여행·바우처 (IDOR) |
| A3 악의적 동행자 | 보기 전용 또는 편집 권한 보유 | 권한 상승, 남의 바우처, 일정 훼손 |
| A4 전 동행자 | 내보내지기 전 받은 ID·URL·캐시 보유 | 내보내진 뒤에도 계속 접근 |
| A5 링크 습득자 | 단톡방 등에서 초대 링크를 얻음 | 초대받지 않은 여행 참여 |
| A6 기기 습득자 | 분실·도난된 폰 | 앱 캐시 속 바우처·토큰 |
| A7 앱 분석가 | 앱 패키지 추출·디컴파일 | 박혀 있는 API 키, 숨은 API |
| A8 공급망 | 악성·취약 패키지 (pub, pip, 컨테이너 이미지) | 서버·앱 내부 장악 |
| A9 나 자신 (운영 실수) | 실수로 비밀값 커밋, 로그에 개인정보, 버킷 공개 | — |

## 4. 위협 목록

심각도: **높음** = 계정 탈취·바우처 유출·대량 노출 / **중간** = 일부 사용자 데이터 노출·무결성 훼손 / **낮음** = 영향 제한적
상태: 계획 → 구현 → 검증(테스트·점검 완료) / 수용(대응하지 않기로 하고 이유 기록)

## 5. 수용하는 위험 (초안)

| 위험 | 이유 |
|---|---|
| 내보낸 멤버의 **기기에 이미 캐시된** 바우처·일정은 원격으로 지울 수 없다 | 오프라인 열람이 핵심 기능이라 피할 수 없음. 다음에 온라인이 되면 앱이 캐시를 지우는 것까지만 대응. 앱 안에서 사용자에게 안내 |
| 루팅·탈옥 기기에서의 키 추출 | 기기 보안 기능에 의존하는 범위 밖. MVP에서는 탐지하지 않음 |

## 6. 열린 질문

- 편집 권한 초대 링크를 아예 막을지, 만료를 짧게 해서 허용할지
- 바우처 속 여권번호가 개인정보 보호법상 고유식별정보 처리에 해당하는지 (6단계에서 확인)
- 현재 위치 표시 기능을 넣을지 — 넣으면 위치정보법 검토 필요
- 서버 저장 암호화를 스토리지 기본 기능으로 할지, 앱 레벨 봉투 암호화로 할지 (3단계)

## 7. 2차 기능 미리보기

MVP 범위 밖이지만 설계할 때 반드시 다시 볼 것:
- **LLM (M2·M3·준비물)**: 장소 리뷰·영수증·바우처 속 글자를 통한 간접 프롬프트 인젝션, LLM 비용 남용, 모델로 보내는 개인정보
- **정산 (M5)**: 금액 계산 정확성, 동시 수정 시 정산 불일치, 남의 지출 수정 권한
- **실시간 편집 (WebSocket)**: 연결 중 권한이 바뀌었을 때 재확인
